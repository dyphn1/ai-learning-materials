# Fact Sheet — OL-20260509-001 (Cron 時區與時間邏輯)

**摘要**
- 本次事實檢核聚焦 OpenClaw 的 cron/timezone 相關邏輯（來源檔案見下列引用），重點確認：時區解析、cron 編譯/快取、next/previous-run 計算、`at`/`every`/`cron` 各類 schedule 的行為、以及維護/修補（maintenance）路徑與相關測試。

**問題陳述**
- 任務要求解析與驗證程式在不同時區、時區邊界及 croner 行為下的時間計算（包含已知 croner year-rollback 問題），並交叉比對測試以確認實際行為與文件一致。

**技術要點（證據導向）**
- 時區解析
  - `resolveCronTimezone(tz?)`：若 schedule 提供 `tz` 字串則採用，否則以系統時區為預設（使用 `Intl.DateTimeFormat().resolvedOptions().timeZone`）。
    - 證據：`openclaw/src/cron/schedule.ts` [L9-L15](openclaw/src/cron/schedule.ts#L9-L15)
- Cron 編譯與快取
  - 使用一個 LRU 風格的 `cronEvalCache: Map<string, Cron>`（上限 `CRON_EVAL_CACHE_MAX=512`），快取鍵為 `${timezone}\u0000${expr}`，避免重複編譯同一 expression+timezone。
  - 編譯時呼叫 `new Cron(expr, { timezone, catch: false })`。
    - 證據：`openclaw/src/cron/schedule.ts` [L6-L7](openclaw/src/cron/schedule.ts#L6-L7), [L17-L35](openclaw/src/cron/schedule.ts#L17-L35)
- `at` / `every` / `cron` 三種調度處理
  - `at`：接受 ISO 字串或數字 epoch；先使用 `parseAbsoluteTimeMs`（見下）解析為 ms，並檢查過期（`computeNextRunAtMs` 的 `at` 分支）。
    - 證據：`openclaw/src/cron/schedule.ts` [L68-L86](openclaw/src/cron/schedule.ts#L68-L86)
  - `every`：計算 anchor、elapsed 與 steps（見程式碼的整除邏輯），回傳下一個時間戳（ms）。
    - 證據：`openclaw/src/cron/schedule.ts` [L88-L102](openclaw/src/cron/schedule.ts#L88-L102)
    - 公式（程式等價）： steps = max(1, floor((elapsed + everyMs - 1) / everyMs))
  - `cron`：透過 `croner` 的 `nextRun(new Date(nowMs))`／`previousRuns(1, new Date(nowMs))` 計算；若 `nextRun` 回傳不晚於 `now`，有兩階段重試策略：再試一次（從 next second）、再試一次（從明日 UTC 起算），以解決 croner 的 year-rollback bug（註：註解明確以 Asia/Shanghai 為示例）。
    - 證據：`openclaw/src/cron/schedule.ts` [L104-L143](openclaw/src/cron/schedule.ts#L104-L143)（workaround 註解 [L117-L120](openclaw/src/cron/schedule.ts#L117-L120)）
- 時間字串解析策略
  - `parseAbsoluteTimeMs(input)`：若為數字字串，視為 epoch（ms）；若為純日期 `YYYY-MM-DD`，補為 `YYYY-MM-DDT00:00:00Z`；若為 datetime 無 timezone，則在尾端補 `Z`，最後交給 `Date.parse`（UTC 處理）。
    - 證據：`openclaw/src/cron/parse.ts` [L5-L16](openclaw/src/cron/parse.ts#L5-L16), [L18-L31](openclaw/src/cron/parse.ts#L18-L31)
- `at` 時間驗證（安全檢查）
  - `validateScheduleTimestamp`：拒絕超過 1 分鐘的過去時間，或超過 10 年的未來時間。
    - 證據：`openclaw/src/cron/validate-timestamp.ts` [L25-L67](openclaw/src/cron/validate-timestamp.ts#L25-L67)
- Stagger 與 per-job offset
  - 每個 cron job 可有 `staggerMs`，系統會使用 `sha256(jobId)` 產生固定 offset（`offset = digest.readUInt32BE(0) % staggerMs`），以確保同表達式下工作在不同時刻分散執行。計算使用 `computeStaggeredCronNextRunAtMs`，其會向後移動 cursor 以命中當前時窗。
    - 證據：`openclaw/src/cron/service/jobs.ts` [L65-L84](openclaw/src/cron/service/jobs.ts#L65-L84), [L86-L112](openclaw/src/cron/service/jobs.ts#L86-L112)
- 維護 / 修補（repair）邏輯
  - `shouldRepairFutureCronNextRunAtMs` 提供一組啟動條件來判斷何時「修復」不合理的未來 `nextRunAtMs`（避免重複或過度遙遠的排程），並由 `recomputeNextRuns` / `recomputeNextRunsForMaintenance` 採用不同策略以避免在主計時路徑無意中前移尚未執行的 nextRun。此邏輯和多個回歸測試交叉驗證。
    - 證據：`openclaw/src/cron/service/jobs.ts` [L179-L238](openclaw/src/cron/service/jobs.ts#L179-L238)（repair 判斷），以及 `recomputeNextRunsForMaintenance`（來源檔）
